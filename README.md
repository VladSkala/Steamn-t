# Steamn’t

Игровой full-stack сервис: магазин, библиотека, сообщество, профили, друзья, чат, уведомления и настройки. Интерфейс использует тёмные фиолетовые поверхности и общие дизайн-токены. Покупки и кошелёк работают в демонстрационном режиме: реальные деньги не списываются, коммерческие лицензии не выдаются.

## Запуск на macOS из архива

Нужны запущенный Docker Desktop и Python 3 для создания локального файла настроек. Распакуйте архив в новую папку, откройте терминал в `steamnt-final` и выполните:

```bash
sh setup-local.sh
docker compose config --quiet
docker compose up --build -d --wait
docker compose exec -T backend python manage.py seed_store_demo
```

Откройте **http://localhost:5180**. Сервер/API: **http://localhost:8010/api/**, администрирование: **http://localhost:5180/admin/**.

`setup-local.sh` создаёт `.env` со случайными локальными секретами. Уже существующий `.env` сохраняется. Новая установка использует имя проекта `steamnt-purple-final`, отдельные постоянные тома и порты 8010/5180. PostgreSQL доступен только внутри Docker; занятый на Mac порт 5432 не мешает запуску.

Каталог заполняется повторяемой командой без изменения паролей или наполнения существующих пользовательских аккаунтов. Создайте аккаунт через интерфейс. Для Django admin:

```bash
docker compose exec backend python manage.py createsuperuser
```

Для наполненных социальных примеров можно отдельно вызвать `seed_store_demo --with-social-demo`. Команда создаёт специально названные демонстрационные аккаунты и печатает сгенерированные пароли; обычный запуск каталога таких аккаунтов не создаёт. Сначала ознакомьтесь с параметрами:

```bash
docker compose exec backend python manage.py seed_store_demo --help
```

## Что работает

- Поиск, жанры, цена, сортировка, страницы каталога; галерея, требования и отзывы игры.
- Регистрация, вход, обновление JWT, возврат на исходную страницу, восстановление и смена пароля с отзывом прежних сессий.
- Wishlist для ещё не купленных игр; корзина; атомарная покупка игры, DLC и набора; постоянное владение в библиотеке; избранное и коллекции.
- Заказы, сохранённая стоимость покупки, печать чека, возврат целого заказа в течение 14 дней. Повторный возврат не начисляет средства дважды.
- Баланс кошелька из неизменяемых операций, страницы истории, повторяемое безопасное пополнение, оплата из кошелька. Симулированная оплата создаёт связанные кредит и списание.
- Публикации разных типов, загрузка изображений/видео, реакции, комментарии, редактирование и удаление владельцем, прямые ссылки.
- Публичные профили, отдельные списки с поиском и сортировкой, приватность, подписки, запросы дружбы, принятие/отклонение/отмена/удаление, блокировка.
- Друзья, Online, Requests, Blocked, поиск и последние публичные публикации принятых друзей.
- Чат: история, ранние сообщения, чтение, изображения, файлы, голосовые вложения, медиа-разделы, отключение уведомлений, очистка своей истории, блокировка и жалоба в admin. Обновление происходит раз в 10 секунд.
- Вложения чата хранятся отдельно от публичных медиа. Скачать их может только авторизованный участник, которому доступно сообщение.
- Настройки профиля, предпросмотр фото, сохранение/отмена, приватность, светлая/тёмная тема и региональный формат дат. Интерфейс остаётся английским; выбор формата дат не является переводом интерфейса.
- События уведомлений: сообщения, дружба, подписка, комментарий, реакция, снижение цены и официальная новость. Предпочтения сохраняются и проверяются при создании события. Звук нового входящего сообщения работает в открытом чате с учётом ограничений браузера на воспроизведение.
- Подтверждённое паролем постоянное удаление аккаунта, его связанных данных и файлов. Удалённые разговоры исчезают и у другого участника; интерфейс предупреждает об этом.

## Архитектура и данные

React 19, React Router 7, Vite 8, Django 6.1, DRF 3.18, PostgreSQL 16. Точные Python-зависимости находятся в `backend/requirements.txt`, JavaScript-зависимости — в `frontend/package-lock.json`.

Docker обслуживает собранный frontend через Nginx 1.28 и backend через Gunicorn. DEBUG отключён. Публичные медиа отдаёт Nginx; приватные вложения — проверяющий права endpoint Django. PostgreSQL, публичные и приватные медиа сохраняются в отдельных Docker-томах.

Обычная остановка сохраняет данные:

```bash
docker compose stop
```

Возобновление:

```bash
docker compose up -d --wait
```

Не используйте `down -v`, если нужны существующие данные. Перед обновлением старой установки сохраните дамп БД и оба тома медиа. Перенос существующей пользовательской PostgreSQL-базы в ходе этой проверки не выполнялся; это отдельная операция с резервной копией.

## Восстановление пароля

Локально письмо с одноразовой ссылкой выводится в журнал backend:

```bash
docker compose logs --tail=100 backend
```

Ссылка действует один час. Для реальной доставки настройте `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`, `DEFAULT_FROM_EMAIL` в `.env` и пересоздайте backend. `FRONTEND_URL` должен соответствовать адресу, открываемому пользователем. SMTP-доставка во внешний почтовый сервис не проверялась.

Сборка не сопровождается обещанием абсолютного отсутствия ошибок или полного закрытия исторического roadmap.

## Разработка на Mac

Для Django, запущенного вне Docker, включите отдельное отображение PostgreSQL на свободный порт 55433:

```bash
sh setup-local.sh
docker compose -f docker-compose.yml -f docker-compose.host-db.yml up -d db
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cd backend
python manage.py migrate
DJANGO_DEBUG=True python manage.py runserver 8002
```

Во втором терминале, из корня проекта:

```bash
cd frontend
npm ci
VITE_PROXY_TARGET=http://127.0.0.1:8002 npm run dev -- --port 5175
```

Этот режим отличается от основной сборки Docker и предназначен для изменения исходников.

## Если порт всё-таки занят

Измените `BACKEND_PORT` и/или `FRONTEND_PORT` в `.env`, затем запустите `docker compose up -d --wait`. Пересборка frontend для этого не нужна: API использует тот же origin. Для нового адреса восстановления пароля проверьте `FRONTEND_URL`. Не останавливайте чужие контейнеры ради этой установки.
