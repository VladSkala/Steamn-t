# KAN-28 — Design rework · QA

Активная карточка: KAN-28. Колонка: IN PROGRESS.
Ветка: `feature/KAN-28-frontend-wishlist`. База: `d810447`.
Это QA-сборка, не подтверждение FINAL/DONE и не основание автоматически делать commit/merge.

## Что изменено

- Home: игровой баннер с ручным переключением и миниатюрами; landscape/portrait-подборки, жанры, реальные ценовые и бесплатные подборки. Удалены огромный рекламный заголовок, наклонная пустая карточка и повторяющиеся объясняющие блоки.
- Страница игры: компактное название, настоящая галерея и увеличение изображений, боковой блок покупки, описание, отдельная вкладка требований. Нет фиктивных трейлеров, рейтингов, скидок, DLC или изданий.
- Library/Catalog используют один `StoreToolbar`: один input, корректный SVG поиска, одинаковые сортировка и переключатель вида. В Library панель находится над sidebar и результатами.
- All games/Favorites и навигация Header используют общие правила `.ui-nav-tab`: текст, прозрачный фон, отсутствие рамки, тонкое подчёркивание. Плюс не отталкивается к правому краю.
- Из GameCard удалена декоративная метка S, которая находилась под In library. Подтверждённое владение сохранено; купленные игры нельзя повторно добавить в Wishlist/Cart.
- Убран конфликт tablet-layout Library. Удалены 131 устаревшее правило CSS для заменённых контролов/hero; текущие компоненты оформлены в `store-ui.css`.
- Локальный variable Noto Sans: единый шрифт текста, заголовков и форм без Google Fonts/CDN. Лицензия рядом с файлом шрифта.
- Единая спокойная navy/purple-палитра существующих диалогов, более компактная типографика, отступ Profile от Header.
- Collection dialog: закрытие после успешного сохранения, Escape, удержание/возврат фокуса. Ошибки Favorites отображаются рядом с содержимым.
- Фото review: сохранены оба предыдущих hotfix; создание/освобождение object URLs вынесено из state-updater, чтобы не удваиваться в React StrictMode.
- Settings больше не утверждает, что авторизация «ещё не подключена». Страница ведёт к уже существующим настройкам профиля/коллекций; новые preferences/password/wallet API не создавались.

## Backend и данные

Добавлена только необходимая для store-gallery модель `GameScreenshot` и миграция `games/0003_gamescreenshot.py`.
Существующий `GET /api/games/<id>/` дополнен read-only массивом `screenshots`; отдельного Gallery API нет. Изображения редактируются через inline в Django admin у игры.

`seed_store_demo` содержит 12 вымышленных игр, 12 обложек, 36 локальных иллюстраций, жанры, описания, цены и примеры требований. Это concept artwork для учебного проекта, а не скриншоты реально выпущенных игр. Нет фиктивных оценок, отзывов, друзей и продаж. Download URL намеренно пуст.

Повторный запуск не меняет существующие записи и не дублирует файлы. Старые QA/пользовательские игры автоматически не удаляются.
`--with-demo-user` создаёт ТОЛЬКО новый отдельный `steamnt_demo`: 5 игр Library, 4 Wishlist, 2 Cart, 2 Favorites и одну коллекцию. Пароль генерируется случайно и печатается один раз. Если username или demo-email уже заняты, аккаунт, пароль и коллекции оставляются без изменений.

Внутренние Order/OrderItem и существующие social endpoints сохранены. Orders History, Friends API, подарки, публичный Wishlist, второй Profile API и будущие карточки не добавлялись.

## Применение на Mac

Архив содержит полные версии изменённых/добавленных файлов относительно d810447; это cumulative overlay, не отдельный полный clone. Он включает предыдущий v6 candidate и оба hotfix. Накладывать по одному старые hotfix после него НЕ нужно.

1. Останови backend/Vite и сохрани копию текущей папки проекта, если в ней есть свои незафиксированные изменения. Не делай искусственный commit только ради резервной копии.
2. Из корня проекта проверь текущую ветку и распакуй архив:

```bash
cd ~/Projects/steamnt
git branch --show-current
unzip -o ~/Downloads/STEAMNT_KAN-28_DESIGN_REWORK_QA.zip -d .
source .venv/bin/activate
```

Ожидаемая ветка — `feature/KAN-28-frontend-wishlist`. Архив сам не переключает ветки и не выполняет Git-команды.

3. Миграции и backend gate — строго из backend, иначе возможен ложный результат «0 tests»:

```bash
cd ~/Projects/steamnt/backend
python manage.py migrate
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

4. Демо-каталог без изменения аккаунтов:

```bash
python manage.py seed_store_demo
```

Для отдельного заполненного демоаккаунта вместо этого можно выполнить:

```bash
python manage.py seed_store_demo --with-demo-user
```

Сохрани напечатанный пароль. Команда не сбрасывает пароль при повторном запуске. Существующий аккаунт можно использовать как обычно: новые игры доступны в каталоге, а покупки/Wishlist заполняются обычными действиями.

5. Frontend gate — версии package.json/package-lock.json не изменены:

```bash
cd ~/Projects/steamnt
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend run build
```

6. Запуск в двух терминалах:

```bash
# Терминал 1
cd ~/Projects/steamnt
source .venv/bin/activate
cd backend
python manage.py runserver 127.0.0.1:8000
```

```bash
# Терминал 2
cd ~/Projects/steamnt
npm --prefix frontend run dev -- --host 127.0.0.1
```

Открой адрес, напечатанный Vite (обычно http://127.0.0.1:5173). Используй существующий рабочий .env/PostgreSQL проекта; приватные .env, база данных и пользовательские media в архив не входят. Если ранее была открыта другая сборка, сделай hard refresh.

## Критерии приёмки

- Home: все обложки загружаются; баннер/миниатюры переключаются; жанр открывает отфильтрованный Catalog.
- Catalog: прежняя структура сохранена, нет S-плашки под In library; одна кнопка grid/list.
- Library: search/sort/view над обоими столбцами; табы выглядят как Header; игры не опущены отдельным лишним margin; desktop/tablet/mobile без горизонтального скролла страницы.
- Пустые Library/Wishlist/Cart отображаются отдельным новым аккаунтом, не удалением текущих данных.
- Купленная игра: store page показывает In your Library/Open in Library, без Cart/Wishlist; новая покупка появляется в Library и исчезает из Wishlist.
- Галерея меняет выбранную картинку; увеличение закрывается кнопкой/Escape; требования читаемы без внутреннего горизонтального скролла.
- Collections/Favorites: создание/изменение сохраняется, диалог закрывается после ответа сервера, ошибка не ломает всю страницу.
- Review: JPG/PNG/WebP, максимум 4 изображения по 5 MB; добавить/удалить/отменить/сохранить, затем обновить страницу и проверить данные.
- Profile, Cart, Wishlist, Library dialogs: один шрифт и палитра, ничего не перекрывает Header и не уезжает за экран.

Подробные фактические результаты и ограничения среды — в `KAN28_DESIGN_QA_REPORT.md`.
Commit/push/PR — только после локального gate и визуальной приёмки Андреем. Git-операции в этой сборке не выполнялись.
